# DDI Editorial · сохранённые решения

Главная инструкция: [design-system/README.md](../design-system/README.md). Визуальные примеры: [design-system/index.html](../design-system/index.html). Реестр контрактов: [components.json](../design-system/components.json). Значения: [tokens.json](../design-system/tokens.json).

## Область

Новые и редактируемые автономные аналитические HTML-документы и продуктовые страницы DDI в стилистике клиентского цикла / ОСАГО / CJHUB. React-приложение `gravity-app/` остаётся на Gravity UI; эта система не меняет его автоматически.

## Направление

Белая спокойная редакционная страница: тёмный `#16283b`, системный sans-serif для тела, Georgia для крупных заголовков. Тонкие границы и слабые подложки; тяжёлые тени и декоративные градиенты не применяются. Плотность осознанная: связанные элементы компактны, между разделами есть воздух; нет обязательных `100vh` и scroll-snap.

Синий `#2858d9` обозначает действие и выбранный раздел. `#139487` — зелёный индикатор подтверждения; для мелкого текста — семантический `#0b756b`. `#7c3aed` — локальный акцент роли агента, не официальный бренд-токен GigaCode. Обычный вторичный текст и метаданные — `#657486`; исходный `#7b8796` не использовать как мелкий читаемый текст.

## Измерения

- Отступы от базы 4px; плотные карточки 12–16px, разделы 40–56px.
- Контент до 1120px; область сайдбара 216px; поля 48px / 28px / 20px, на широком экране 64px.
- Шапка 80px, мобильная 64px + горизонтальное меню около 61px; учитывать sticky-offset у якорей.
- Действия 44px, компактные 40px; радиус поля/кнопки/карточки 4px, диалога 8px.
- Display Georgia 40–60px / 1.08; заголовки разделов 32–44px / 1.12; текст 14px / 1.6; компактная таблица и подписи 12px / 1.5. Микро-метки 10px — только необязательные.
- Цифры tabular-nums. SVG в тексте 1em, заметные иллюстрации крупнее; не использовать эмоджи вместо иконок.

## Паттерны, которые нельзя потерять

1. **Диалог CJHUB:** карточка запроса → стрелка → отдельный фиолетовый «Агент думает» → стрелка → карточка ответа с таблицей. Внутри агента обязательна графика: крупные `{ }` / JSON → стрелка → мини-воронка из трёх сужающихся полос. Пользователь отклонил текстовый список вместо картинок. Уменьшать отступы, а не удалять стадию агента или его графику.
2. **Чеклист со ссылкой:** нет валидной HTTP(S)-ссылки — нет галочки; есть ссылка — ниже «Перейти →»; удаление снимает подтверждение. Это контракт именно ссылочного варианта. Сохранять явные исключения клиентского цикла: `monthly` — ручная отметка без ссылки; проверенный источник может задать и заблокировать статус без веб-URL, с названием документа/локатором. Не распространять URL-правило на все предметные чекбоксы TAM/SAM и не считать валидный адрес доказательством качества данных.
3. **Числа:** разряды пробелами; единица справа внутри поля; не часть значения. Не ломать курсор форматированием на каждом символе.
4. **Источник:** подтверждённое значение серое и readonly, источник виден; ручное можно менять. Readonly-текст читаем и копируется.
5. **Статус:** светофор и аналитическое пояснение получают одно состояние; цвет сопровождается текстом; отсутствие данных отличается от отрицательного результата.
6. **Роли:** агент явно подписан фиолетовым, человек — обычным текстом; не полагаться только на цвет.
7. **Навигация:** компактные этапы, текущий раздел отмечен; фильтр остаётся доступен при прокрутке. На телефоне не оставлять большой пустой сайдбар.
8. **Достоверность:** пример обозначен как пример; нет выдуманных чисел, источников, кейсов и причинных обещаний. Пустое значение — «—», а не ноль.

## Как применять и поддерживать

Сначала переиспользовать компонент из реестра и семантические CSS-переменные. Для подключения брать сгенерированный `design-system/ddi.css`. Токены менять в JSON, стили — в `components.css`, примеры — в `catalog.template.html` / `catalog.js`. `tokens.css`, `ddi.css` и `index.html` собираются, вручную не редактируются.

```sh
node design-system/build.mjs
node design-system/build.mjs --check
node --test design-system/design-system.test.mjs
```

Обновлять контракт, каталог и CHANGELOG вместе. Для нового паттерна указывать потребность, основание и состояния. Версии, статусы и миграции описаны в README. Не добавлять дополнительное разрешение пользователя на обычную уже согласованную работу; соблюдать действующий AGENTS.md и независимую приёмку reviewer.

Проверять реальный рендер на 320/390/1280/1440 CSS px, клавиатуру, контраст и отсутствие обрезанного текста. Исходные страницы и Gravity UI не мигрировать без задачи на их изменение.
