# Сборка клиентского цикла агентом

`index.html` — самостоятельный шаблон. Данные находятся внутри `script#report-data` (`type="application/json"`); сеть и сервер для открытия не нужны. Этот JSON содержит исходные значения, источники, заполнение чеклистов и индивидуальные рекомендации по Вкладам и Прайму. Сам HTML ничего не запрашивает у ИИ.

## Как агент готовит файл пользователю

1. Заполнить лежащую рядом книгу `report-inputs.xlsx`: лист «Данные» — значения, результаты задач и их источники; лист «Рекомендации» — индивидуальные рекомендации и события SAM. В строке 3 листа «Данные» задать уникальный `reportId` для этой версии отчёта, например `lifecycle-2026-11-16-team-a`, и `generatedAt` в ISO-формате. `selectedProduct` — `deposits` или `prime`. Ключи и структуру листа «Данные» сохранять. Строки рекомендаций можно добавлять ниже заголовка; строки без заголовка и описания пропускаются. Альтернатива Excel — скопировать JSON из `script#report-data` в рабочий `report.json`.
2. Заполнить `products.deposits` и `products.prime` по доступным материалам. Числа не придумывать: если значения нет, оставить `null`. Источник указывать у каждого подтверждённого поля, включая отметки методики и результаты задач. Ссылки на отчёты в продажах класть в `sales.<ключ>.url`.
3. Заполнить `recommendations` и `samGrowthEvents` для каждого продукта. Это индивидуальные выводы агента по материалам, а не стандартный список. В `description` объяснять сигнал/потребность, предлагаемое действие и ожидаемый результат; для события — критерий отбора аудитории и способ проверки гипотезы. Не выдавать предложение за проверенный факт и не обещать объём роста без расчёта. При наличии основания указать `source`. Если обоснованных предложений нет, оставить массив пустым.
4. Запустить сборку:

   ```sh
   node outputs/customer-lifecycle-2026-11-13/build-report.mjs --data outputs/customer-lifecycle-2026-11-13/report-inputs.xlsx --output /absolute/path/customer-report.html
   ```

5. Открыть итоговый HTML, проверить оба продукта, источники и расчёт покрытия. Передать пользователю **собранный HTML**: все значения и рекомендации уже встроены в файл, отдельный JSON для просмотра не требуется.

При работе через Excel агент получает цепочку **Excel → JSON внутри HTML → готовый отчёт**. Изменение книги после сборки не меняет уже выданный HTML: нужно собрать новую версию. Колонки источника: название, HTTP/HTTPS-ссылка и раздел/период; пустой источник означает ручной ввод. Для отметок используйте «Да» / «Нет». Для чисел пропуск отличается от нуля. Не заменяйте неизвестные значения нулями. В книгу перенесены текущие ручные значения Прайма: SAM 20 000 000 и потенциал 15 000 000, без подтверждающего источника. Числа Вкладов и рекомендации пока пустые; наличие TAM/SAM предзаполнено по договорённости с пользователем.

Чтение XLSX использует `@oai/artifact-tool` из установленного пакета либо Codex runtime (`~/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules`). Для другого расположения задайте `ARTIFACT_NODE_MODULES`. Сборка из JSON не требует этой зависимости.

## Контракт JSON, версия 1

Корневые поля: `schemaVersion: 1`, `reportId`, `generatedAt` (ISO-строка или `null`), `selectedProduct`, `products`. Каждый продукт содержит:

| Поле | Формат |
| --- | --- |
| `market.tamApproved`, `market.samApproved` | `{ "value": true, "source": null }` |
| `market.samVolume`, `market.identified` | `{ "value": null, "source": null }`, значение — неотрицательное число или числовая строка |
| `sales.reporting`, `sales.monthly`, `sales.process`, `sales.journey` | `{ "checked": false, "url": "", "source": null }` |
| `recommendations` | Массив `{ "title": "…", "description": "…", "source": null }` |
| `samGrowthEvents` | Массив того же формата — «События, предложенные ИИ, для роста SAM» |

`source` — `null` для ручного ввода либо объект `{ "title": "Название документа", "url": "https://…", "locator": "Лист/раздел/период" }`. Название обязательно, ссылка и указатель на место необязательны. Допустимы только абсолютные ссылки HTTP/HTTPS. Для локального документа достаточно названия и раздела. Не добавлять источник только ради блокировки: он должен подтверждать конкретное значение. Для больших целых можно передавать строку, чтобы не потерять цифры при сериализации; расчёт покрытия использует обычную числовую точность JavaScript.

## Поведение готового отчёта

- Поля с источником серые и заблокированы. Название/ссылка на источник показаны рядом. Сохранённые ручные изменения не подменяют подтверждённое значение.
- Поля без источника можно корректировать. Изменения сохраняются в браузере для конкретного `reportId` и продукта; исходный HTML на диске при этом не перезаписывается. При передаче другому пользователю он получает значения, встроенные агентом во время сборки.
- Покрытие SAM, светофор и числовой анализ пересчитываются на месте. Границы: ≥95% — зелёный, ≥80% — жёлтый, ниже — красный, по отображаемому значению с одним десятичным знаком.
- Рекомендации и события отображаются из JSON, включая случаи без достаточных чисел для светофора. После изменения ручных исходных данных появляется предупреждение об актуальности выводов; новые рекомендации должен подготовить агент и пересобрать файл с новым `reportId`.
- Для ручных чеклистов продаж, кроме помесячной воронки, отметка требует ссылки на результат. Подтверждающий источник, который агент указал в JSON, позволяет поставить отметку и блокирует изменение соответствующего пункта; это может быть локальный документ с названием и разделом без веб-ссылки.

Проверки: `node --test outputs/customer-lifecycle-2026-11-13/*.test.mjs`.
