DDI Editorial.

Спокойная форма для сложных данных. Токены, компоненты и рабочие примеры для аналитических документов и продуктовых страниц.

Белая бумага. Чёткая иерархия.
Цвет сообщает смысл.

Область применения — standalone HTML. Основой служат выбранные решения клиентского цикла, опросника ОСАГО и страницы CJHUB. React-интерфейсы Gravity остаются в своей системе компонентов.

Все примеры в каталоге демонстрационные. Фильтр переключает локальные состояния образцов; это не отчёт по продуктам и не результат пилота.

Типографика

Данные ведут историю.

Крупный заголовок — Georgia. Рабочий текст и интерфейс — системный sans-serif, 14 px. Подписи — 12 px; 10 px остаются для необязательных метаданных.

Сетка и ритм

Контент — до 1120 px. Отступы — 4 / 8 / 12 / 16 / 24 / 32 / 48. На узком экране колонки складываются, навигация становится горизонтальной.

Тонкие линии разделяют смысловые блоки. Карточка нужна для отдельного объекта, а не для каждого абзаца.

Источник, значение,
подтверждение.

Редактируемое поле, данные из источника и подтверждённый пункт должны отличаться по поведению, а не только по цвету.

ед.

Источник: учебный пример. Объём — в условных единицах; значение не редактируется.

Чеклист с подтверждением

  • Перейти

    Для отметки нужна ссылка на подтверждение.

Контракт поведения

Для этого варианта без корректной HTTP(S)-ссылки пункт нельзя отметить. Сохранение ссылки отмечает пункт; после этого отметку можно изменить. Удаление ссылки сбрасывает состояние.

Состояния и валидация 
{ checked: false, url: '' }
checked ⇒ valid HTTP(S) URL
remove URL ⇒ unchecked + disabled

Этот URL-gate — для пунктов с подтверждением ссылкой. Ручные и sourced-варианты задаются контрактом задачи. Локальные правки не должны подменять поля из источника.

Использовать текстовый статус рядом с цветом. Расчёт покрытия и блок пояснения получают один результат функции.

Избегать зелёной отметки по умолчанию, отдельно вычисленного цвета предупреждения и единицы измерения под полем.

Что сохраняем при повторном использовании

  1. Запрос и ответ выделены как элементы диалога.
  2. Между ними — фиолетовый блок работы агента с JSON и графикой воронки.
  3. Стрелки показывают последовательность до и после стадии агента.
  4. Числа в таблице появляются только из настоящего расчёта. В демонстрации стоят «—».
  5. Четыре колонки остаются читаемыми на ширине 320 px. Числовые значения используют tabular-nums.

03Работа с CJHUB

Завершающий элемент набора. Нативный details работает мышью и клавиатурой.

  • Используйте вкладки для параллельных сценариев, а не для последовательных шагов.
  • Arrow Left / Right, Home и End перемещают фокус и активируют вкладку.
  • Details подходит для описаний навыков, FAQ и дополнительной методики.
  • Не вкладывайте кнопку или ссылку внутрь другого интерактивного контрола.
